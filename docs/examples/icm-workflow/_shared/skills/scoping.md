# Skill — Scoping

## When to load
Stage 1. Any time the input is an ambiguous request.

## Core moves
1. **Restate in one sentence.** If you cannot compress the request into a single sentence without losing meaning, the request is under-specified.
2. **Name the audience concretely.** "Compliance leads at hospital systems" beats "healthcare people". Concrete audience → concrete register.
3. **Fix the format before the content.** Word count, venue, medium. This bounds every later stage.
4. **Decompose into RQs, not sections.** Research questions are what you ask sources. Sections come later.
5. **Estimate effort per RQ.** S = one search + one primary source. M = several sources, some paywalled. L = interviews or novel analysis. Flag any L for human review before Stage 2.

## Anti-patterns
- "Comprehensive overview" as a success criterion.
- Merging two audiences into one deliverable ("execs and engineers").
- Skipping the out-of-scope list. Without it, scope creep is guaranteed.

## Halt conditions
- Two or more plausible interpretations of the request remain.
- The reviewer has not named a venue or format.
- Success criteria cannot be phrased as testable statements.
